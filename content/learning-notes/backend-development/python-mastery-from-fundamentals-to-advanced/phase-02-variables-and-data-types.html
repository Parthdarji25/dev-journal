Phase 02 — Variables & Data Types

Objects, variables as references, assignment, dynamic typing, int, float, complex, bool, str, None, type(), id(), type conversion, mutable vs immutable objects, and == vs is.

#python#phase-02#python-foundations#variables#objects#references#memory-model#data-types#mutability#identity

Phase 02 — Variables & Data Types (Part I: Python Foundations). In Python every value is an object, and a variable is just a name that refers to an object. Once that picture is clear, assignment, copying, mutation and == vs is all make sense.

Every concept below has the same eight parts: beginner explanation, internal explanation, code examples, common mistakes, debugging examples, practical exercises, interview questions and tricky questions. Try each exercise and question before reading its answer.

Key ideas

  • Every value is an object with an identity (id()), a type (type()) and a value.
  • A variable is a name tag pointing at an object. It doesn't contain the value and has no type of its own.
  • b = a copies the reference, not the object: both names now point at the same object.
  • Re-binding a name (a = 20) never affects other names. Mutating an object (a.append(3)) is seen by every name pointing at it.
  • Python is dynamically typed (names can point at any type) but strongly typed ("5" + 5 is an error).
  • int has unlimited size; float is approximate (0.1 + 0.2 != 0.3); bool is a subclass of int.
  • None is the single "no value" object. Test it with is None.
  • Immutable: int, float, complex, bool, str, tuple, None. Mutable: list, dict, set.
  • == asks "same value?"; is asks "same object?". Use is only for None.

How to read the memory diagrams

Names live on the left; objects live in memory on the right. An arrow means "this name refers to this object."

 NAMES                OBJECTS IN MEMORY
                     ┌──────────────────┐
 a ────────────────▶ │ int   10         │
                     └──────────────────┘

When two arrows point at one box, both names share the same object.

1. Objects

Beginner explanation

A running program has to keep data somewhere in memory: a number, a name, a list of users. In Python, every piece of data lives in an object, a small chunk of memory that knows three things about itself:

Part Question it answers How to see it Can it change?
Identity Which object is this? id(obj) Never, for its whole life
Type What kind of thing is it? What can it do? type(obj) Never
Value What data does it hold? the object itself Only if the type is mutable

"Everything is an object" is literal: numbers, strings, None, lists, functions, classes, even types themselves.

Why it exists: one uniform model makes Python simple. Every value can be stored in a variable, put in a list, passed to a function, compared and printed in exactly the same way. There are no special "primitive" values with different rules, as in Java or C.

Internal explanation

In CPython, every object begins with the same small header:

 one object in memory
┌──────────────────────────────┐
│ reference count   2          │  ← how many references point here
│ type pointer   ──────────────┼──▶ <class 'int'>   (decides what it can do)
├──────────────────────────────┤
│ value             42         │  ← the actual data
└──────────────────────────────┘
 its address in memory = id(obj) in CPython
  • The type pointer is why the object always knows its type, and why type() can answer instantly.
  • The reference count tracks how many names, lists and other objects refer to it. When it drops to zero, Python frees the memory automatically (Phase 26).
  • Even a small int is a full object: about 28 bytes on 64-bit CPython (sys.getsizeof(1)), far more than the 4 or 8 bytes a C integer uses. That's the price of "everything is an object."

Code examples

x = 42
print(type(x))     # <class 'int'>    → its type
print(id(x))       # 140735928821064  → its identity (a different number on your machine)
print(x)           # 42               → its value

values = [10, 3.5, "hi", True, None, [1, 2]]
for value in values:
    print(value, "→", type(value).__name__)   # every one of them is an object with a type

10 → int
3.5 → float
hi → str
True → bool
None → NoneType
[1, 2] → list

Real-world: checking what an API actually sent before using it.

response_value = "1499"            # looks like a number, but what is it really?
print(type(response_value))        # <class 'str'> → must convert before doing maths
price = int(response_value)
print(type(price), price * 2)      # <class 'int'> 2998

Common mistakes

count = 5
count.upper()      # AttributeError: 'int' object has no attribute 'upper'

Why: the type decides what an object can do. upper() is a string method; int objects don't have it.

  • Thinking numbers are "simpler" than other values. In Python they're objects too, with a type, an identity and methods: (255).bit_length() → 8.

Debugging examples

D1. Why does this crash?

age = 25
print(age.title())

Answer: AttributeError: 'int' object has no attribute 'title'. title() belongs to strings. Use str(age) if you want text; otherwise don't call string methods on a number.

D2. A function receives quantity and crashes on quantity * 2 + 1 with TypeError: can only concatenate str (not "int") to str. How do you find the cause quickly?

Answer: print the type: print(type(quantity), repr(quantity)). It shows <class 'str'> '3': the value came in as text ("3" * 2 is "33", then "33" + 1 fails). Convert it with int(quantity) where the data enters the program.

Practical exercises

E1. For name = "Ravi", which of identity, type and value can ever change while that object exists?

Answer: none. Strings are immutable, so even the value can't change. name can later point at a different object, but this object stays as it is.

E2. Print the type of 7, 7.0, "7" and [7].

Answer: int, float, str, list: four different objects that all "look like 7" to a human.

Interview questions

Q1. What does "everything in Python is an object" mean? Every value, including numbers, strings, None, functions and classes, is an object with an identity, a type and a value, and they can all be stored, passed and inspected the same way.

Q2. What three properties does every object have? Identity (id()), type (type()) and value. Identity and type never change; the value changes only for mutable objects.

Tricky questions

T1. Is a class an object?

Answer: yes. type(int) is <class 'type'>. Classes are objects whose type is type, and you can store them in variables: t = int; t("5") → 5.

T2. What does type(type) return?

Answer: <class 'type'>. type is its own type: the one place where the chain of "what is the type of this?" ends.

2. Variables and references

Beginner explanation

A variable is a name that refers to an object. It's not a box that holds the value. Think of a name tag (or sticky note) attached to an object:

  • One object can have many name tags.
  • A name tag can be moved to a different object at any time.
  • The object doesn't know or care which names point at it.

Why it exists: references are efficient and flexible. Passing a list of a million items to a function passes one reference, not a million copies. This one idea also explains all of Python's "surprising" behaviour with lists and dictionaries, so it's worth getting right on day one.

Internal explanation

Names are stored in a namespace, which is really a dictionary that maps a name (a string) to a reference to an object. At the top level of a file, you can see it with globals():

price = 100
print(globals()["price"])     # 100 → the name "price" is a key in a dict

The classic example, step by step:

a = 10
b = a
a = 20
print(a, b)    # 20 10

Step 1: a = 10        a ──────▶ ┌────────┐
                                │ int 10 │
                                └────────┘

Step 2: b = a         a ──────▶ ┌────────┐
                      b ──────▶ │ int 10 │     ← b copies the REFERENCE: both tags on one object
                                └────────┘

Step 3: a = 20        a ──────▶ ┌────────┐
                                │ int 20 │     ← a's tag MOVES to a new object
                                └────────┘
                      b ──────▶ ┌────────┐
                                │ int 10 │     ← b is untouched
                                └────────┘

The same thing with a mutable list:

a = [1, 2]
b = a
a.append(3)
print(b)       # [1, 2, 3]

Step 2: b = a         a ──────▶ ┌─────────────┐
                      b ──────▶ │ list [1, 2] │
                                └─────────────┘

Step 3: a.append(3)   a ──────▶ ┌────────────────┐
                      b ──────▶ │ list [1, 2, 3] │   ← the ONE shared object changed
                                └────────────────┘

The rule that explains everything:

Operation What happens Do other names see it?
Re-binding: a = something The name tag moves to another object No
Mutating: a.append(x), a[0] = x, a["k"] = v The object itself changes Yes, every name pointing at it

Code examples

cart = ["pen", "notebook"]
checkout_cart = cart              # same list, second name
checkout_cart.append("bag")       # modifies the one shared list
print(cart)                       # ['pen', 'notebook', 'bag']

Real-world, done correctly: keeping a real backup before editing.

original = ["pen", "notebook"]
backup = original.copy()      # a NEW list with the same items
backup.append("bag")
print(original)               # ['pen', 'notebook'] → unchanged
print(backup)                 # ['pen', 'notebook', 'bag']

Common mistakes

settings = ["dark_mode"]
backup = settings             # ❌ not a copy: two names, one list

Fix: backup = settings.copy() (or list(settings)). Nested data needs copy.deepcopy() (Phase 27).

print(total)
total = 100                   # NameError: name 'total' is not defined

Why: the name isn't bound to any object yet when line 1 runs.

Debugging examples

D1. A developer saves a "backup" before editing, but the backup changes too. Why? Fix it.

settings = ["dark_mode", "notifications"]
backup = settings
settings.remove("notifications")
print(backup)          # ['dark_mode']  ← backup was supposed to keep both

Answer: backup = settings copied the reference, so both names point at one list, and remove() mutated it. Fix: backup = settings.copy().

D2. Why does y not change here, when the list version did?

x = "hello"
y = x
x = x.upper()
print(y)       # hello

Answer: x.upper() builds a new string, and x = ... re-binds x to it. That's re-binding, not mutation, so y still points at the original "hello". (Strings can't be mutated anyway.)

Practical exercises

E1. Predict the output, then draw the memory diagram.

x = 5
y = x
x = x + 1
print(x, y)

Answer: 6 5. x + 1 creates a new object 6 and moves the x tag to it; y still points at 5.

E2. Predict the output.

x = [1, 2]
y = x
y.append(3)
print(x)

Answer: [1, 2, 3]. x and y are two names for one list, and append changes it in place.

Interview questions

Q1. What is a variable in Python? A name bound to an object, stored in a namespace (essentially a dictionary). The variable holds a reference, not the value itself.

Q2. What's the difference between re-binding a name and mutating an object? Re-binding (a = ...) moves one name to a different object and affects no other name. Mutating (a.append(...)) changes the object, and every name referring to it sees the change.

Tricky questions

T1. Predict the output.

a = [1, 2]
b = a
a = a + [3]
print(b)

Answer: [1, 2]. a + [3] builds a new list, and a = ... re-binds a. Nothing mutated the original list, so b is unchanged.

T2. Predict the output.

a = [1, 2]
b = a
a += [3]
print(b)

Answer: [1, 2, 3]. For lists, += mutates in place (it calls extend), so the shared list changes. a = a + [3] and a += [3] are not the same for lists.

3. Assignment

Beginner explanation

Assignment binds a name to an object: name = expression. The = sign doesn't mean "equals" as in maths. Read it as "make this name refer to this value."

Why it exists: programs need to remember results so they can use them later: a price, a user's name, a running total.

Naming rules: letters, digits and underscores; can't start with a digit; case-sensitive; can't be a keyword (class, if, for, …). Style (PEP 8): snake_case for variables, UPPER_CASE for constants.

Internal explanation

  1. Python evaluates the right-hand side first, producing an object.
  2. Then it stores a reference to that object under the name(s) on the left (the STORE_NAME bytecode instruction from Phase 1).
Form Example What really happens
Simple x = 5 bind x to the object 5
Unpacking x, y = 1, 2 build the tuple (1, 2), then bind each name
Swap x, y = y, x the right side is fully built from the old values first, then unpacked
Chained a = b = [] one object, two names
Augmented n += 1 immutable n: build a new object, re-bind. Mutable list: change it in place 
a = b = []

a ──────▶ ┌──────────┐
b ──────▶ │ list []  │     ← ONE list, not two
          └──────────┘

Code examples

count = 0
count += 1             # right side (count + 1) is evaluated first, then count is re-bound
count += 1
print(count)           # 2

Real-world: unpacking and swapping without a temporary variable.

width, height = 1920, 1080          # unpack two values at once
width, height = height, width       # rotate the screen: swap them
print(width, height)                # 1080 1920

MAX_LOGIN_ATTEMPTS = 5              # UPPER_CASE signals "constant, don't change this"

Common mistakes

2nd_place = "Ravi"       # SyntaxError: invalid decimal literal
class = "Python 101"     # SyntaxError: invalid syntax
user name = "Asha"       # SyntaxError: invalid syntax

Why: names can't start with a digit, be keywords, or contain spaces. Use second_place, course_name, user_name.

a, b = 1, 2, 3           # ValueError: too many values to unpack (expected 2)

Why: unpacking needs exactly as many names as values.

visited = unvisited = []   # ❌ two names, ONE list
visited.append("Pune")
print(unvisited)           # ['Pune']

Fix: visited = [] and unvisited = [] on separate lines.

Debugging examples

D1. This swap doesn't work. Why? Fix it.

x = 5
y = 9
x = y
y = x
print(x, y)        # 9 9

Answer: after x = y, the object 5 has no name left, so y = x just copies 9 back. Use x, y = y, x → 9 5.

D2. Two counters always show the same list of events. Why?

login_events = error_events = []
login_events.append("login")
print(error_events)          # ['login']

Answer: chained assignment binds both names to one list object. Create two lists: login_events = [] and error_events = [].

Practical exercises

E1. Predict the output.

a = 1
b = 2
a, b = b, a + b
print(a, b)

Answer: 2 3. The right side (b, a + b) is fully evaluated with the old values, giving (2, 3), then unpacked.

E2. Which names are valid? total_price, _hidden, price$, for, Price2, 2price.

Answer: valid: total_price, _hidden, Price2. Invalid: price$ (symbol), for (keyword), 2price (starts with a digit).

Interview questions

Q1. In x = y + 1, what happens first? The right-hand side is evaluated to an object, then the name x is bound to it.

Q2. How does Python swap two variables without a temporary? a, b = b, a: the right side builds a tuple from the current values first, then unpacks it into the names.

Tricky questions

T1. Predict the output.

a = b = 5
a += 1
print(b)

Answer: 5. Both names start on the same int object, but ints are immutable, so a += 1 creates 6 and re-binds only a.

T2. Predict the output.

a = b = [5]
a += [6]
print(b)

Answer: [5, 6]. Same shape as T1, different result: lists are mutable and += changes the shared list in place.

4. Dynamic typing

Beginner explanation

In some languages (Java, C, Go) you declare a variable's type, and it can only ever hold that type: int age = 25;. That's static typing. In Python, names have no type; objects do. A name can point at an int now and a str later. That's dynamic typing: types are checked while the program runs.

Why it exists:

  • Less code to write; faster to experiment.
  • The same code can work with many types that behave alike ("duck typing": if it walks like a duck and quacks like a duck, treat it as a duck).
  • The trade-off: some type mistakes only show up at runtime, so professionals add type hints and checkers (Phase 24).

Internal explanation

  • The type is stored in the object (its type pointer). The namespace only stores name → reference, with no type information at all.
  • When an operation runs, for example BINARY_OP +, the virtual machine looks at the types of the actual objects at that moment and picks the right behaviour: number addition, string joining, list concatenation, or a TypeError.
  • Python is also strongly typed: it won't silently convert between unrelated types. "5" + 5 raises TypeError instead of guessing "55" or 10. (JavaScript, a weakly typed language, gives "55".)
  • Type hints (age: int = 25) are stored as metadata in __annotations__. The interpreter ignores them when running code.
namespace (dict)                 objects
┌─────────────────┐
│ "value" ────────┼──────▶  int 42         ← after value = 42
└─────────────────┘
┌─────────────────┐
│ "value" ────────┼──────▶  str "forty"    ← after value = "forty": same name, new object, new type
└─────────────────┘

Code examples

value = 42          # value → int
value = "forty"     # now value → str: allowed
print(type(value))  # <class 'str'>

Real-world: values from outside are always checked and converted, because the name tells you nothing about the type.

quantity = input("Quantity: ")     # always a str, even if the user typed 3
quantity = int(quantity)           # re-bind the name to an int object
total: float = quantity * 249.5    # type hint documents the intended type
print(f"₹{total:.2f}")

Common mistakes

print("Age: " + 25)    # TypeError: can only concatenate str (not "int") to str

Why: dynamic doesn't mean weak. Use f"Age: {25}" or "Age: " + str(25).

age: int = "hello"     # runs without any error!

Why: type hints aren't enforced at runtime. A type checker like mypy would flag it; Python won't.

  • Re-using one name for different types (data = "5", later data = 5, later data = [5]) makes code hard to follow. Use different, descriptive names.

Debugging examples

D1. Why does this crash, and what are two fixes?

items = 3
message = "You have " + items + " items"

Answer: TypeError: can only concatenate str (not "int") to str. Python won't auto-convert. Fixes: f"You have {items} items" (best) or "You have " + str(items) + " items".

D2. This function works for total(2, 3) but gives "23" for total("2", "3"). Why doesn't Python stop you?

def total(a, b):
    return a + b

Answer: with dynamic typing, + does whatever the objects' types define: numbers add, strings join. Nothing checks the types beforehand. Convert inputs at the boundary (int(a)), and add hints def total(a: int, b: int) -> int: so a type checker can catch bad calls.

Practical exercises

E1. Is Python statically or dynamically typed? Strongly or weakly? Give one line of code that shows each.

Answer: dynamically: x = 1 then x = "one" works. Strongly: "1" + 1 raises TypeError.

E2. Does score: int = "high" raise an error? Why?

Answer: no. Type hints aren't checked at runtime; only tools like mypy or your editor warn.

Interview questions

Q1. Dynamic vs static typing? Static: types are attached to variables and checked before running (Java, Go). Dynamic: types are attached to objects and checked while running (Python).

Q2. Is Python weakly typed because it's dynamic? No. It's dynamic and strong: it refuses to implicitly mix unrelated types such as str and int.

Tricky questions

T1. What does "3" * 3 give? And "3" + 3?

Answer: "333" (repeating a string by an int is defined), but "3" + 3 is a TypeError. Whether an operation works depends on the types involved, not on whether it "looks like maths."

T2. Does this line raise an error: x: int = 3.7?

Answer: no. x is 3.7, a float. Hints are documentation for tools, not runtime checks.

5. int

Beginner explanation

int represents whole numbers: positive, negative or zero, with no fractional part. -3, 0, 42, 10_000_000.

Why it exists: counting, indexing, IDs, quantities and money stored in the smallest unit (paise, cents) all need exact whole numbers. Integers are exact: no rounding errors.

Internal explanation

  • CPython ints have unlimited precision. The value is stored as an array of 30-bit chunks ("digits") that grows as needed, so 2 ** 100 is exact. (Many languages overflow past about 9.2 quintillion.)
  • Bigger numbers use more memory: sys.getsizeof(1) is 28 bytes; sys.getsizeof(2**100) is 40 bytes (64-bit CPython 3.13).
  • Small-int cache: CPython creates the ints from -5 to 256 once at startup and reuses them everywhere. Every 5 in your program is the same object. Bigger ints created at runtime are new objects. This is an optimisation, not a language rule.
  • Ints are immutable: n += 1 creates (or reuses) another object and re-binds n.
n = 5            n ──▶ int 5   (from the shared small-int cache)
n += 1           n ──▶ int 6   ← a different object; 5 is untouched
  • / always returns a float (7 / 2 → 3.5); // is floor division (rounds down: -7 // 2 → -4); % is the remainder (-7 % 2 → 1).
  • int(3.9) → 3 and int(-3.9) → -3: converting a float truncates toward zero. It doesn't round.

Code examples

students = 32
groups = 5
print(students // groups)   # 6  → full groups
print(students % groups)    # 2  → students left over
print(2 ** 100)             # 1267650600228229401496703205376 → exact
print(0b1010, 0o17, 0xFF)   # 10 15 255 → binary, octal, hex literals
print(int("FF", 16))        # 255 → parse hex text

Real-world: storing money as an integer number of paise to avoid float errors.

price_paise = 149_900              # ₹1,499.00 stored exactly
quantity = 3
total_paise = price_paise * quantity
print(f"₹{total_paise // 100}.{total_paise % 100:02d}")   # ₹4497.00

Common mistakes

pages = 10 / 2
print(pages, type(pages))        # 5.0 <class 'float'>  ← not an int!

Why: / always produces a float. Use // for a whole-number result.

int("3.5")     # ValueError: invalid literal for int() with base 10: '3.5'

Why: int() only parses whole-number text. Use int(float("3.5")) if truncation is really what you want.

  • Expecting int() to round: int(2.9) is 2. Use round(2.9) → 3 when you want rounding.

Debugging examples

D1. range(pages) crashes. Why? Fix it.

items = 50
per_page = 10
pages = items / per_page
for page in range(pages):
    print(page)

Answer: / returns 5.0, and range() needs an int: TypeError: 'float' object cannot be interpreted as an integer. Use pages = items // per_page.

D2. Splitting a ₹-7 refund into 2 parts gives -4 per part. Why?

print(-7 // 2)     # -4

Answer: // rounds down (toward negative infinity), not toward zero. For "truncate toward zero" use int(-7 / 2) → -3. Better: decide explicitly how refunds should round.

Practical exercises

E1. Predict: 17 // 5, 17 % 5, 17 / 5, int(7.99), int(-7.99).

Answer: 3, 2, 3.4, 7, -7.

E2. Convert 3725 seconds into hours, minutes and seconds using // and %.

Answer:

total = 3725
hours = total // 3600              # 1
minutes = (total % 3600) // 60     # 2
seconds = total % 60               # 5
print(f"{hours}h {minutes}m {seconds}s")   # 1h 2m 5s

Interview questions

Q1. Can a Python int overflow? No. Python ints have arbitrary precision and grow as needed, limited only by memory.

Q2. What's the difference between / and //? / is true division and always returns a float. // is floor division and rounds down; with two ints it returns an int.

Tricky questions

T1. Predict: a = int("256"); b = int("256"); print(a is b), then the same with 257.

Answer: True, then False (in CPython). 256 is inside the small-int cache, so both names get the cached object; 257 isn't, so int() creates two separate objects. Never rely on this: compare numbers with ==.

T2. Predict: -7 // 2, -7 % 2, int(-7 / 2).

Answer: -4, 1, -3. Floor division rounds down; int() truncates toward zero. Python keeps (a // b) * b + a % b == a true.

6. float

Beginner explanation

float represents numbers with a fractional part: 3.14, -0.5, 2.0, 1e3 (= 1000.0).

Why it exists: measurements, percentages, averages, scientific values and coordinates need fractions and a huge range of sizes.

The one thing every beginner must know: floats are approximations. 0.1 + 0.2 is 0.30000000000000004, not 0.3.

Internal explanation

  • A float is stored as a 64-bit IEEE 754 double, the same format almost every language uses: 1 sign bit, 11 exponent bits and 52 fraction bits. That gives about 15–17 significant digits and a range up to about 1.8e308 (sys.float_info.max).
  • The number is stored in binary. Many decimal fractions, such as 0.1, can't be written exactly in binary, just as 1/3 can't be written exactly in decimal (0.3333…). Python stores the nearest possible binary value:
print(f"{0.1:.30f}")     # 0.100000000000000005551115123126 → what is REALLY stored
  • When you print 0.1, Python shows the shortest text that maps back to the same stored value, which is why it looks exact until you do arithmetic.
  • round() uses "banker's rounding" for exact halves: round(2.5) → 2, round(3.5) → 4 (round half to even).
  • Special values: float("inf"), float("-inf") and float("nan") (not a number). nan is not equal even to itself.
  • For money, use integers in the smallest unit (paise) or decimal.Decimal, created from strings.

Code examples

temperature = 36.6
average = (90 + 85 + 77) / 3
print(round(average, 2))      # 84.0
print(1e3, type(1e3))         # 1000.0 <class 'float'>

import math

result = 0.1 + 0.2
print(result)                         # 0.30000000000000004
print(math.isclose(result, 0.3))      # True → compare floats with a tolerance
print(f"{result:.2f}")                # 0.30 → format for display

Real-world: exact money calculations with Decimal.

from decimal import Decimal

price = Decimal("0.10")
total = price + Decimal("0.20")
print(total)                          # 0.30 → exact
print(total == Decimal("0.30"))       # True

Common mistakes

if 0.1 + 0.2 == 0.3:        # ❌ False
    print("Equal")

Fix: math.isclose(0.1 + 0.2, 0.3).

Decimal(0.1)     # Decimal('0.1000000000000000055511151231257827021181583404541015625')

Why: creating a Decimal from a float copies the float's error. Pass a string: Decimal("0.1").

  • Storing money as floats. Small errors add up across thousands of transactions. Use paise (int) or Decimal.

Debugging examples

D1. A discount check never passes. Why? Fix it.

discount = 1 - 0.9
if discount == 0.1:
    print("10% discount applied")

Answer: 1 - 0.9 is 0.09999999999999998. Use math.isclose(discount, 0.1), or store percentages as integers (discount_percent = 10).

D2. A shop's total of three ₹0.10 items shows ₹0.30000000000000004 on the receipt. Fix the display and the calculation.

Answer: for display, format it: f"₹{total:.2f}". For the calculation itself, use Decimal("0.10") * 3 or integer paise (10 * 3 paise), so the stored value is exact.

Practical exercises

E1. Predict: round(2.5), round(3.5), 0.1 * 3, float("nan") == float("nan").

Answer: 2, 4, 0.30000000000000004, False.

E2. Total ₹0.10, ₹0.20 and ₹0.30 so the result prints exactly 0.60.

Answer:

print(total)          # 0.60

Interview questions

Q1. Why is 0.1 + 0.2 != 0.3 in Python? Floats are binary IEEE 754 doubles. 0.1 and 0.2 can't be represented exactly in binary, so their sum is the nearest double to 0.30000000000000004, not exactly 0.3. It's the same in almost every language.

Q2. How should you handle money in Python? Use integers in the smallest currency unit, or decimal.Decimal created from strings. Never plain floats.

Tricky questions

T1. Predict the output.

x = float("nan")
print(x == x, [x] == [x])

Answer: False True. nan is never equal to itself. But list comparison first checks whether the elements are the same object (is), and here they are, so the lists compare equal.

T2. Predict: round(0.5), round(1.5), round(2.675, 2).

Answer: 0, 2, 2.67. Exact halves round to the even number; and 2.675 is really stored as 2.67499999…, so it rounds down.

7. complex

Beginner explanation

A complex number has a real part and an imaginary part: 3 + 4j. In maths the imaginary unit is written i (√−1); Python, like electrical engineering, writes j.

Why it exists: complex numbers are essential in electrical engineering, signal processing and physics. Python builds them in so basic use needs no library. As a backend developer you'll rarely need them, but you should recognise them.

Internal explanation

  • A complex object stores two floats: the real part and the imaginary part. So both parts have float precision and float rounding behaviour.
  • .real and .imag return those floats; abs(z) returns the magnitude √(real² + imag²).
  • Complex numbers support + - * / and **, but not ordering (<, >): there's no natural "bigger" for points on a plane.
  • Numeric types widen automatically: int → float → complex (1 + 2j + 3 is (4+2j)).
  • The cmath module has complex versions of math functions.

Code examples

z = 3 + 4j
print(z.real, z.imag)    # 3.0 4.0
print(abs(z))            # 5.0 → distance from 0 (a 3-4-5 triangle)
print(type(z))           # <class 'complex'>
print(complex(3, 4) == z)  # True

Real-world: the impedance of a circuit (resistance + reactance).

resistance = 30            # ohms
reactance = 40             # ohms
impedance = complex(resistance, reactance)
print(abs(impedance))      # 50.0 ohms: the total opposition to current

Common mistakes

print(3 + 4j < 1 + 1j)

TypeError: '<' not supported between instances of 'complex' and 'complex'

Why: complex numbers have no natural order. Compare abs() values or the parts.

z = 3 + 4i      # SyntaxError: invalid decimal literal

Why: Python uses j, not i.

Debugging examples

D1. Why does sorted([3 + 1j, 1 + 1j]) crash, and how do you sort by size?

Answer: sorting compares items with <, which complex numbers don't support (TypeError). Sort by magnitude: sorted([3 + 1j, 1 + 1j], key=abs) → [(1+1j), (3+1j)].

D2. j = 2 then z = 3 + j gives 5, not a complex number. Why?

Answer: without a digit in front, j is just a variable name. The imaginary literal needs a number: 3 + 1j.

Practical exercises

E1. Predict: (2 + 3j).imag, abs(6 + 8j), type(5j), 1 + 2j + 3.

Answer: 3.0, 10.0, <class 'complex'>, (4+2j).

Interview questions

Q1. How is a complex number stored in Python? As two floats, the real and imaginary parts, available as .real and .imag.

Q2. Why can't you sort complex numbers directly? They have no natural ordering, so < isn't defined. Sort with a key, such as abs.

Tricky questions

T1. What is the type of (1 + 2j).real?

Answer: float (1.0), even though you wrote an int. Both parts are always stored as floats.

T2. Is 1 + 0j == 1 true?

Answer: yes. Numbers of different types compare equal when their values are equal: 1 + 0j == 1.0 == 1.

8. bool

Beginner explanation

bool has exactly two values: True and False. It answers yes/no questions: "Is the user logged in?" "Is the cart empty?"

Why it exists: every decision in a program, every if and every while, comes down to true or false. Comparisons (>, ==, in) produce bools.

Truthiness: every object can be used in a condition. These are falsy; almost everything else is truthy:

Falsy values
False, None
0, 0.0, 0j
empty collections: "", [], (), {}, set(), range(0)

Internal explanation

  • bool is a subclass of int: True behaves as 1 and False as 0. So True + True == 2, and isinstance(True, int) is True.
  • There are exactly two bool objects in the whole program. True and False are singletons, so bool(1) is True is True.
  • When Python needs a truth value (if x:), it asks the object: first its __bool__ method; if there isn't one, its __len__ (zero length → false); otherwise it's true. That's why empty containers are falsy.
  • and/or return one of the operands, not necessarily a bool: "" or "Guest" → "Guest".

Code examples

age = 20
is_adult = age >= 18        # comparison → bool
print(is_adult)             # True
print(bool(""), bool("hi")) # False True
print(True + True)          # 2 → bool is an int

Real-world: Pythonic checks that rely on truthiness.

cart_items = []
coupon_code = ""

if not cart_items:                  # empty list is falsy
    print("Your cart is empty")
if coupon_code:                     # empty string is falsy
    print("Applying coupon")

display_name = "" or "Guest"        # `or` returns the first truthy operand
print(display_name)                 # Guest

Common mistakes

is_active = true    # NameError: name 'true' is not defined. Did you mean: 'True'?

Why: the values are capitalised: True, False.

answer = "False"          # text from a form or config file
if bool(answer):
    print("Subscribed")   # prints! bool("False") is True

Why: any non-empty string is truthy. Compare the text: answer.strip().lower() == "true".

  • Writing if is_active == True:. Just write if is_active:.

Debugging examples

D1. A feature flag from a config file is always on, even when it says "false". Fix it.

feature_flag = "false"          # read from a config file as text
if feature_flag:
    print("New checkout enabled")

Answer: "false" is a non-empty string, so it's truthy. Parse it: enabled = feature_flag.strip().lower() == "true", then if enabled:.

D2. A count of "approved" orders is 3 even though the list holds booleans, not numbers. Is that a bug?

approved = [True, False, True, True]
print(sum(approved))        # 3

Answer: not a bug. It's a common idiom: True counts as 1, so sum() counts the True values. Just be aware it works because bool is a subclass of int.

Practical exercises

E1. Predict: bool(0), bool(0.0), bool(" "), bool([0]), bool(None), True + True + False.

Answer: False, False, True (a space is a character), True (a list with one item), False, 2.

E2. Rewrite if len(names) > 0: in a more Pythonic way.

Answer: if names:.

Interview questions

Q1. What values are falsy in Python? False, None, numeric zeros (0, 0.0, 0j) and empty collections ("", [], (), {}, set(), range(0)). Almost everything else is truthy.

Q2. Why is isinstance(True, int) true? bool is a subclass of int; True and False behave as 1 and 0.

Tricky questions

T1. Predict the output.

print({True: "a", 1: "b"})

Answer: {True: 'b'}. True == 1 and they have the same hash, so they're the same key. The first key object (True) is kept and its value is overwritten with "b".

T2. Predict: 0 or "default", "" and "x", [] or [] or "last".

Answer: "default", "", "last". or returns the first truthy operand (or the last one); and returns the first falsy operand (or the last one).

9. str

Beginner explanation

str represents text: a sequence of characters. "Asha", '₹499', "नमस्ते", "" (the empty string). Phase 4 covers strings in depth; here you need them as a data type.

Why it exists: names, messages, emails, JSON, HTML, file contents and user input are all text. Most programs handle more strings than any other type.

  • Create with single or double quotes; triple quotes ("""...""") span multiple lines.
  • len(s) counts characters; s[0] is the first character; + joins; * repeats.
  • Strings are immutable: methods like .upper() return a new string.

Internal explanation

  • A str is an immutable sequence of Unicode code points (each character has a number: ord("A") → 65, ord("₹") → 8377).
  • CPython stores each string compactly using 1, 2 or 4 bytes per character, depending on the widest character in it. ASCII-only text uses 1 byte per character; adding one ₹ switches that string to 2 bytes per character.
  • len() counts characters, not bytes: len("₹") is 1, but its UTF-8 encoding is 3 bytes (len("₹".encode()) → 3).
  • Because strings are immutable, every "change" builds a new object:
name = "asha"           name ──▶ str "asha"
name = name.title()     name ──▶ str "Asha"     ← NEW object; "asha" is untouched
  • CPython interns (reuses) some strings automatically, mostly short identifier-like ones such as "user_id". That's an optimisation; never rely on it.

Code examples

name = "asha"
print(len(name))         # 4
print(name[0])           # a
print(name.title())      # Asha → a NEW string
print(name)              # asha → original unchanged
print("ha" * 3)          # hahaha

Real-world: cleaning user input before saving it.

raw_email = "  Asha.Rao@Example.COM  "
email = raw_email.strip().lower()     # each method returns a new string
print(email)                          # asha.rao@example.com

Common mistakes

name = "asha"
name[0] = "A"      # TypeError: 'str' object does not support item assignment

Why: strings are immutable. Build a new one: name = "A" + name[1:] or name = name.capitalize().

name = "asha"
name.upper()
print(name)        # asha  ← the result of upper() was thrown away

Why: upper() returns a new string. Assign it: name = name.upper().

Debugging examples

D1. The username is stored in lowercase, but this check fails for Asha. Fix it.

stored = "asha"
typed = "Asha"
typed.lower()
print(typed == stored)       # False

Answer: typed.lower() returns a new string that's thrown away. Use it: print(typed.lower() == stored) → True.

D2. A database field holds at most 10 bytes. The check passes, but the database rejects the value. Why?

text = "₹₹₹₹"
if len(text) <= 10:
    save(text)          # rejected: value too long

Answer: len() counts characters (4), not bytes. Each ₹ is 3 bytes in UTF-8, so the value is 12 bytes. When a limit is in bytes, check len(text.encode("utf-8")) <= 10.

Practical exercises

E1. Predict: len("₹500"), "5" + "5", "5" * 2, str(3.0).

Answer: 4, "55", "55", "3.0".

E2. Turn " ravi KUMAR " into "Ravi Kumar" in one line.

Answer: " ravi KUMAR ".strip().title().

Interview questions

Q1. Are Python strings mutable? No. Every method that "changes" a string returns a new string object.

Q2. What's the difference between characters and bytes in a string? A str holds Unicode characters; len() counts those. Bytes appear only when you encode the text (e.g. UTF-8), where one character can take 1–4 bytes.

Tricky questions

T1. Predict the output.

s = "hi"
t = s
s += "!"
print(t)

Answer: hi. Strings are immutable, so s += "!" builds a new string and re-binds only s.

T2. Predict: len("नमस्ते").

Answer: 6. The word looks like 3–4 letters, but it's made of 6 Unicode code points (consonants plus combining vowel signs), and len() counts code points.

10. None

Beginner explanation

None means "no value" or "nothing here yet." It isn't 0, not "" and not False; it's the absence of a value.

Why it exists: programs constantly need to say "not set," "not found" or "optional": a user with no middle name, a search with no result, a setting nobody chose. None makes that explicit instead of using a fake value like -1 or "".

Internal explanation

  • There is exactly one None object in a running program. Its type is NoneType, and even calling that type gives back the same object: type(None)() is None → True.
  • Because it's a singleton, x is None is the correct, fastest and conventional test.
  • Functions that finish without return return None, which is why print() returns None.
  • None is falsy, but so are 0 and "", so if not x: can't tell "missing" from "zero" or "empty."
  • Calling a method on None raises AttributeError: 'NoneType' object has no attribute ..., one of the most common errors in real code.
a = None         a ──▶ ┌──────────────┐
b = None         b ──▶ │ the ONE None │     ← every None in the program is this object
                       └──────────────┘

Code examples

middle_name = None
print(middle_name)            # None
print(type(middle_name))      # <class 'NoneType'>
print(middle_name is None)    # True

Real-world: an optional discount that may not have been set.

discount = None            # no discount chosen yet

if discount is None:
    print("No discount applied")
else:
    print(f"Discount: {discount}%")

is None matters here: a discount of 0 is a real value ("0% off") and must not be treated as missing.

Common mistakes

discount = 0
if not discount:
    print("No discount set")     # ❌ prints, but 0 WAS set

Fix: if discount is None: when you mean "missing."

user = None
print(user.upper())   # AttributeError: 'NoneType' object has no attribute 'upper'

Fix: check for None before using a value that might be missing.

  • value == None works but isn't idiomatic. Write value is None.

Debugging examples

D1. A user who chose a score of 0 is told they haven't chosen one. Fix it.

score = 0            # user picked 0
if not score:
    print("Please choose a score")

Answer: 0 is falsy. Represent "not chosen" with None and check if score is None:.

D2. Why does name end up as None?

name = print("Asha")
print(name.upper())

Answer: print() returns None, so name is None and .upper() raises AttributeError. Assign the value itself: name = "Asha".

Practical exercises

E1. Predict: None == 0, None == False, bool(None), None is None.

Answer: False, False, False, True.

E2. Write a check that prints "Guest" when nickname is None, and the nickname otherwise (even if it's an empty string).

Answer:

nickname = None
print("Guest" if nickname is None else nickname)

Interview questions

Q1. Why use is None instead of == None? None is a singleton, so identity is the precise test. == can be overridden by a class to return surprising results; is can't.

Q2. What does a function return if it has no return statement? None.

Tricky questions

T1. Predict: print(None or 0 or "").

Answer: an empty line. or returns the first truthy operand; none are truthy, so it returns the last one, "".

T2. Is [] == None? Is not []?

Answer: [] == None is False (an empty list isn't None), but not [] is True (empty lists are falsy). Falsy is not the same as None.

11. type() and isinstance()

Beginner explanation

Every object knows its type. type(obj) asks, "What kind of thing are you?" and returns the class it was made from. isinstance(obj, SomeType) asks, "Are you this kind of thing, or a more specific version of it?"

Why it exists: data from outside (user input, JSON, files, other people's code) may not be the type you expect, so you check before using it. It's also the first debugging step: "Why does this crash? Oh, it's a str, not an int."

Internal explanation

  • type(obj) simply follows the object's type pointer (section 1) and returns that class object.
  • Types are objects too, and their type is type: type(int) → <class 'type'>.
  • isinstance(obj, cls) checks the object's class and all its parent classes. Python records that chain in __mro__ ("method resolution order"):
print(bool.__mro__)    # (<class 'bool'>, <class 'int'>, <class 'object'>)

So isinstance(True, int) is True, but type(True) is int is False.

  • isinstance(x, (int, float)) checks several types at once.
  • Professional habit: use isinstance() for checks; use type() mainly to print and debug.

Code examples

print(type(42))              # <class 'int'>
print(type(4.2))             # <class 'float'>
print(type("42"))            # <class 'str'>
print(isinstance(42, int))   # True
print(type(42).__name__)     # int → just the name, handy in messages

Real-world: validating a value from a JSON request before doing maths (Pydantic automates this in Phase 52).

data = {"quantity": "3"}            # came from a client: is it really a number?

quantity = data["quantity"]
if isinstance(quantity, int) and not isinstance(quantity, bool):
    print("OK")
else:
    print(f"Expected int, got {type(quantity).__name__}")   # Expected int, got str

Common mistakes

value = 5
if type(value) == "int":     # ❌ never true
    print("integer")

Why: type() returns a class, not the text "int". Use isinstance(value, int).

is_admin = True
print(isinstance(is_admin, int))    # True ← surprise

Why: bool is a subclass of int. When True must not count as a number, add not isinstance(x, bool).

Debugging examples

D1. A price-check function rejects every number. Fix it.

def is_number(x):
    return type(x) == "float" or type(x) == "int"

print(is_number(9.99))     # False

Answer: type(x) is a class object and never equals a string. Use return isinstance(x, (int, float)) and not isinstance(x, bool).

D2. An API accepts {"age": true} from JSON as a valid age of 1. Why did isinstance(age, int) let it through?

Answer: JSON true becomes Python True, and bool is a subclass of int. Reject bools explicitly: isinstance(age, int) and not isinstance(age, bool).

Practical exercises

E1. Predict: type(3 / 1), type(3 // 1), type(None), type(type(1)).

Answer: <class 'float'>, <class 'int'>, <class 'NoneType'>, <class 'type'>.

E2. Predict: isinstance(True, int), isinstance(3, float), isinstance(3.0, (int, float)).

Answer: True, False, True.

Interview questions

Q1. Difference between type(x) is int and isinstance(x, int)? type() checks the exact class only. isinstance() also accepts subclasses, so it's the usual choice for checks; it returns True for True because bool subclasses int.

Q2. What is the type of a class? type. Classes are objects created by type; type(int) is <class 'type'>.

Tricky questions

T1. Predict: type(True) is int, isinstance(True, int).

Answer: False, True. The exact type is bool, but bool is a subclass of int.

T2. Predict: isinstance(int, type), isinstance(type, object).

Answer: True, True. int is an instance of type, and everything, including type, is an object.

12. id()

Beginner explanation

id(obj) returns a number that uniquely identifies an object while it exists. Two objects alive at the same time never share an id.

Why it exists: it lets you check whether two names point at the same object or just at equal values. That's exactly what is tests. It's mainly a learning and debugging tool.

Internal explanation

  • In CPython, id(obj) is the object's memory address.
  • a is b compares those addresses, so it's the same as id(a) == id(b), only faster.
  • An object's id never changes during its lifetime.
  • When an object is destroyed, its memory, and therefore its id, can be reused by a new object. Only compare ids of objects that are alive at the same time.
  • The numbers themselves are meaningless and differ on every run.
  • Because CPython caches small ints (-5 to 256) and interns some strings, equal immutable values may or may not share an id. That's an implementation detail.
a = [1, 2]          a ──▶ list @ 0x7f..10   [1, 2]
b = a               b ──▶ (same address)              id(a) == id(b)  → True
c = [1, 2]          c ──▶ list @ 0x7f..90   [1, 2]    id(a) == id(c)  → False

Code examples

a = [1, 2]
b = a
c = [1, 2]
print(id(a) == id(b))    # True  → same object
print(id(a) == id(c))    # False → equal value, different object

Real-world: proving whether an operation changed your list in place or gave you a new one.

scores = [70, 90, 80]
before = id(scores)

scores.sort()                       # sorts in place
print(id(scores) == before)         # True → same list, modified

ranked = sorted(scores)             # builds a new list
print(id(ranked) == before)         # False → a different object

Common mistakes

a = 1000
b = 1000
print(a is b)      # True in a script, False when typed line by line in the REPL

Why: whether equal immutable values share one object depends on how the code was compiled and on caching. Code that depends on it is buggy. Compare values with ==.

  • Using id() as a permanent identifier. It's only valid while the object exists, within one run.

Debugging examples

D1. A developer logs id() values to "track a user record" across two program runs, and they never match. Why?

Answer: each run creates new objects at new addresses, and ids can be reused after objects die. Use a real identifier stored with the data, such as a database primary key.

D2. id(n) changes after n += 1. Did something go wrong?

Answer: no. int is immutable, so n += 1 binds n to a different object (6 instead of 5). The id belongs to the object, not to the name.

Practical exercises

E1. After x = [1] and y = x, then y = [1], are id(x) and id(y) equal?

Answer: no. y = [1] creates a new list and moves y to it; x still points at the original.

E2. Use id() to show that text += "!" creates a new string but items += ["x"] does not create a new list.

Answer:

text = "hi"
before = id(text)
text += "!"
print(id(text) == before)    # False → new str object

items = ["a"]
before = id(items)
items += ["x"]
print(id(items) == before)   # True → same list, changed in place

Interview questions

Q1. What does id() return in CPython? The object's memory address: an integer unique among objects that exist at the same time.

Q2. How are is and id() related? a is b is equivalent to id(a) == id(b).

Tricky questions

T1. Predict: print(id([]) == id([])).

Answer: usually True in CPython. The first empty list is created, its id taken, and then it's destroyed immediately; the second list is often built at the same freed address. The two lists were never alive at the same time, so their ids can match. This is why ids must only be compared for live objects.

T2. Can two different objects ever have the same id?

Answer: not at the same time. One after the other, yes: the second can reuse the first one's memory.

13. Type conversion

Beginner explanation

Type conversion (casting) creates a new object of a different type from an existing value: the text "42" → the number 42. The original object is never changed.

Why it exists: data arrives in the wrong type constantly. input(), files, URLs, environment variables and CSV cells are all text, but you need numbers for maths and strings for display. Python is strongly typed, so you convert explicitly.

Function Converts to Examples
int(x) whole number int("42") → 42; int(3.9) → 3 (truncates); int("FF", 16) → 255
float(x) decimal number float("3.5") → 3.5; float(5) → 5.0
str(x) text str(42) → "42"; str(None) → "None"
bool(x) truthiness bool(0) → False; bool("0") → True
list(x), tuple(x), set(x) collections list("abc") → ['a', 'b', 'c']

Internal explanation

  • int, float, str and the others are classes. Calling one, such as int("42"), builds a brand-new object of that class.
  • Each class knows how to read certain inputs: int() parses digit text or asks a number for its integer part; str() asks the object for its text form (its __str__ method, Phase 18).
  • Implicit conversion happens only between numbers, always toward the "wider" type: int → float → complex (3 + 2.0 → 5.0). Python never implicitly converts between text and numbers.
  • Text that doesn't represent the target type raises ValueError (int("abc"), int("")); the wrong kind of object raises TypeError (int(None)).
age_text = "25"        age_text ──▶ str "25"
age = int(age_text)    age      ──▶ int 25       ← a NEW object; "25" still exists unchanged

Code examples

age_text = "25"
age = int(age_text)
print(age + 1)                # 26
print(str(age) + " years")    # 25 years
print(3 + 2.0)                # 5.0 → implicit int → float

Real-world: reading configuration from environment variables, which are always strings.

import os

port = int(os.environ.get("PORT", "8000"))                   # "8000" → 8000
debug = os.environ.get("DEBUG", "false").lower() == "true"   # text → bool, done safely
timeout = float(os.environ.get("TIMEOUT", "2.5"))
print(port, debug, timeout)                                  # 8000 False 2.5

Common mistakes

int("3.5")       # ValueError: invalid literal for int() with base 10: '3.5'
int("")          # ValueError: invalid literal for int() with base 10: ''
float("abc")     # ValueError: could not convert string to float: 'abc'
int(None)        # TypeError: int() argument must be a string, a bytes-like object or a real number, not 'NoneType'

Why: conversion only works when the value really represents the target type. Validate input and handle errors with try/except (Phase 12).

bool("False")    # True!

Why: bool() checks emptiness, not meaning.

  • Forgetting to keep the result: int(age_text) on its own line converts and throws the result away. Assign it.

Debugging examples

D1. The total prints 102030 instead of 60. Fix it.

a = input("Score 1: ")    # 10
b = input("Score 2: ")    # 20
c = input("Score 3: ")    # 30
total = a + b + c
print(total)

Answer: the inputs are strings, so + joins them. Convert first: a = int(input("Score 1: ")) and so on → 60.

D2. A CSV import crashes on some rows with ValueError: invalid literal for int() with base 10: ''. What's in those rows, and what should the code do?

Answer: the cell is empty (""), and int("") can't produce a number. Decide what an empty cell means: treat it as missing (None), use a default, or report the row. Check with if cell.strip() == "": before converting.

Practical exercises

E1. Predict: int(" 7 "), int(-2.7), float("1e3"), str(1/2), int(True), bool("0").

Answer: 7, -2, 1000.0, "0.5", 1, True.

E2. Convert the CSV row "Asha,29,55.5" into a name (str), an age (int) and a weight (float).

Answer:

row = "Asha,29,55.5"
name, age_text, weight_text = row.split(",")
age = int(age_text)
weight = float(weight_text)
print(name, age, weight)       # Asha 29 55.5

Interview questions

Q1. Does int("42") change the string? No. It creates a new int object. Strings are immutable, and conversion always produces a new object.

Q2. When does Python convert types implicitly? Only between numeric types, widening int → float → complex in arithmetic. Never between strings and numbers.

Tricky questions

T1. Predict: int("0x1F", 16), int("1_000"), float(" -0.5\n").

Answer: 31 (a 0x prefix is allowed with base 16), 1000 (underscores are allowed in numeric text too), -0.5 (surrounding whitespace is ignored).

T2. Predict: str(None) == "None" and bool(str(None)).

Answer: True and True. str(None) is the 4-letter text "None", which is a non-empty, truthy string, not the None object.

14. Mutable vs immutable objects

Beginner explanation

  • An immutable object's value can never change after it's created. Any "change" makes a new object.
  • A mutable object's value can change in place. It stays the same object (same id) while its contents change.
Immutable Mutable
int, float, complex, bool, str, tuple, frozenset, bytes, None list, dict, set, bytearray, most objects of your own classes

Why it exists:

  • Immutable objects are safe to share: nobody can change them behind your back. They can be hashed, so they can be dictionary keys and set members.
  • Mutable objects are efficient for data that grows and changes (a cart, a cache) without copying everything each time.

Internal explanation

Immutable: "changing" means re-binding to a new object.

a = 10
b = a
a = a + 5

before:   a ──▶ int 10 ◀── b
after:    a ──▶ int 15          int 10 ◀── b      ← 10 never changed; a moved

Mutable: changing means the shared object itself changes.

a = [10]
b = a
a.append(15)

before:   a ──▶ list [10] ◀── b
after:    a ──▶ list [10, 15] ◀── b               ← one object, both names see it
  • += uses an in-place method (__iadd__) when the type has one. Lists do, so x += [1] mutates the list. Ints, strings and tuples don't, so += builds a new object.
  • Hashing: a dict finds keys by their hash. If a key could change, its hash would change and the dict would lose it. That's why only hashable (generally immutable) objects can be keys: {[1]: "x"} fails.
  • A tuple is immutable, but it holds references. If one of them points at a list, that list can still change.
point = (1, [2])

point ──▶ tuple (  ref 0  ,  ref 1  )
                     │          │
                     ▼          ▼
                   int 1     list [2]    ← the tuple can't change WHICH objects it holds,
                                           but this list is still mutable

Code examples

name = "asha"
name_id = id(name)
name = name.title()              # new string object
print(id(name) == name_id)       # False

cart = ["pen"]
cart_id = id(cart)
cart.append("bag")               # same list, changed in place
print(id(cart) == cart_id)       # True

Real-world: a shared "default" list leaking between users.

default_tags = ["new"]
user_a_tags = default_tags          # shares the SAME list
user_b_tags = default_tags.copy()   # gets its own copy

user_a_tags.append("vip")
print(default_tags)    # ['new', 'vip'] ← the shared default was changed!
print(user_b_tags)     # ['new']        ← safe, because it was copied

locations = {(19.07, 72.87): "Mumbai"}   # tuple (immutable) works as a dict key

Common mistakes

locations = {[19.07, 72.87]: "Mumbai"}   # TypeError: unhashable type: 'list'

Why: list keys could change. Use a tuple.

point = (1, [2])
point[1].append(3)
print(point)       # (1, [2, 3])  ← the "immutable" tuple's contents changed

Why: the tuple holds a reference to a mutable list.

  • Assuming b = a gives an independent copy of a list or dict. It doesn't; use .copy().

Debugging examples

D1. Every new order contains items from earlier orders. Fix it.

empty_order = []
order_1 = empty_order
order_1.append("pen")
order_2 = empty_order
print(order_2)            # ['pen'] ← should be empty

Answer: both orders are names for the one list empty_order. Create a new list for each: order_1 = [], order_2 = [].

D2. A grid built with * changes a whole column when you set one cell. Why?

grid = [[0] * 3] * 3
grid[0][0] = 1
print(grid)        # [[1, 0, 0], [1, 0, 0], [1, 0, 0]]

Answer: [row] * 3 repeats the reference to one inner list three times, so all three rows are the same object. Build separate rows: grid = [[0] * 3 for _ in range(3)] (comprehensions, Phase 8).

Practical exercises

E1. Sort into mutable and immutable: 42, "hi", [1, 2], (1, 2), {"a": 1}, {1, 2}, None, 3.5.

Answer: immutable: 42, "hi", (1, 2), None, 3.5. Mutable: [1, 2], {"a": 1}, {1, 2}.

E2. Predict the output.

a = "hi"
b = a
a += "!"
x = [1]
y = x
x += [2]
print(b, y)

Answer: hi [1, 2]. a += "!" made a new string, so b keeps "hi". x += [2] changed the shared list in place.

Interview questions

Q1. Why can't a list be a dictionary key? Dict keys must be hashable, and a list's contents (and so its hash) could change after insertion, which would break lookups. Use a tuple.

Q2. Is a tuple always fully immutable? The tuple itself is: you can't add, remove or replace its items. But if an item is a mutable object, like a list, that object can still change.

Tricky questions

T1. Predict what happens.

t = (1, [2])
t[1] += [3]

Answer: it raises TypeError: 'tuple' object does not support item assignment, and t is now (1, [2, 3]). += first extends the list in place (that succeeds), then tries to store the result back into the tuple (that fails). Both steps happen.

T2. Predict: x = (1, 2); y = x; x += (3,); print(y).

Answer: (1, 2). Tuples have no in-place +=, so a new tuple is built and only x is re-bound.

15. Equality vs identity (== vs is)

Beginner explanation

There are two different questions you can ask about two objects:

  • Equality, ==: "Do they have the same value?" Two separate ₹500 notes are equal.
  • Identity, is: "Are they the same object?" Is this the exact same note?

Why it exists: sometimes you care about content (do these two carts contain the same items?), and sometimes about the object itself (is this the one and only None?). Python gives each question its own operator.

Rule: use == for values. Use is only for singletons such as None.

Internal explanation

  • a == b asks the objects to compare themselves (their __eq__ method, Phase 18). Each type decides what "equal" means, and different types can be equal: 5 == 5.0 and 1 == True are both True.
  • a is b compares identities: in CPython, whether both names hold the same memory address. It can't be customised and is very fast.
  • Python warns when you use is with a literal: SyntaxWarning: "is" with 'int' literal. Did you mean "=="?
a = [1, 2, 3]       a ──▶ ┌──────────────┐
c = a               c ──▶ │ list [1,2,3] │      a is c  → True    a == c → True
                          └──────────────┘
b = [1, 2, 3]       b ──▶ ┌──────────────┐
                          │ list [1,2,3] │      a is b  → False   a == b → True
                          └──────────────┘

Code examples

a = [1, 2, 3]
b = [1, 2, 3]
c = a
print(a == b)    # True  → same value
print(a is b)    # False → two different list objects
print(a is c)    # True  → c is another name for a

Real-world: compare data by value, check optional fields by identity.

stored_hash = "5f4dcc3b"
submitted_hash = "5f4dcc3b"          # e.g. computed from what the user typed
print(submitted_hash == stored_hash)  # True → compare VALUES

nickname = None
if nickname is None:                  # identity check for the None singleton
    nickname = "Guest"
print(nickname)                       # Guest

Common mistakes

answer = input("Continue? ")      # user types yes
if answer is "yes":               # ❌ SyntaxWarning, and may be False
    print("Continuing")

Why: the typed text is a new string object, so it's usually not the same object as the literal "yes". Use ==.

if value == None:     # works, but not idiomatic

Fix: if value is None:.

Debugging examples

D1. This check passes in quick tests but fails in production. Fix it.

MAX = 1000
count = int("1000")          # value read from a file
if count is MAX:
    print("Limit reached")

Answer: int("1000") creates a new object at runtime, which isn't the same object as MAX (CPython only caches -5 to 256). Use if count == MAX:.

D2. A "has the cart changed?" check always says it changed, even when the items are the same. Why?

saved_cart = ["pen", "bag"]
current_cart = ["pen", "bag"]       # rebuilt from the database
if current_cart is not saved_cart:
    print("Cart changed")

Answer: is not asks whether they're different objects, and they always are. The question is about contents, so use if current_cart != saved_cart:.

Practical exercises

E1. Predict: [1] == [1], [1] is [1], 5 == 5.0, 1 == True, "1" == 1, None is None.

Answer: True, False, True, True, False, True.

E2. Which operator for each? (a) is the response None? (b) are two carts identical in content? (c) did sort() modify my original list or give me a new one?

Answer: (a) is, (b) ==, (c) is (or compare id()), because you're asking about the object itself.

Interview questions

Q1. What's the difference between == and is? == compares values, using the type's __eq__. is compares identity: whether both names refer to the same object.

Q2. When should you use is? For singletons, mainly None (x is None). Never for comparing numbers or strings.

Tricky questions

T1. Predict: print({1, 1.0, True}).

Answer: {1}. 1 == 1.0 == True and all three have the same hash, so a set treats them as one element and keeps the first one added.

T2. Predict the output.

a = 256
b = 256
c = int("257")
d = int("257")
print(a is b, c is d, c == d)

Answer: True False True in CPython. 256 comes from the small-int cache; the two 257s are created separately at runtime. Only == gives an answer you can rely on.
